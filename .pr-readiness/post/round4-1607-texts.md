## Thread reply — root 3989965346 (asclearuc), thread PRRT_kwDOROCxS86hgBuJ
I tested this before touching it, and I think the current code is right. cmark-gfm's cell scanner takes the longest match over "lone backslash | escaped punctuation pair", so n backslashes before a pipe parse as n−1 lone backslashes plus `\|` — for every n ≥ 1 the pipe stays escaped and the row does not split; unescaping then strips exactly one. Rendering through cmark-gfm: today's emitted `\d+\\|x` gives a 3-column row and the cell `\d+\|x`; the proposed `\d+\\\|x` also keeps 3 columns but renders `\d+\\|x`, an extra backslash. GitHub's own `/markdown` API agrees: `\d+\\|x` renders `\d+\|x`, the doubled form renders `\d+\\|x`. So I left `_md_cell` as it is, documented the rule in the docstring, and added two tests — exact emitted bytes (runs in CI) and a cmark-gfm round-trip (skips when cmarkgfm is absent, which it is in CI; `pip install cmarkgfm` runs it). Happy to change it if you have a rendered counter-example.
