## 4. Findings

### PR1866-F1 — "both stay empty at `'none'`" is false when the pipeline invokes tools — **P2**, confidence high
- **File:line:** the clause appears in all five changed files — `docs/agents/ROCKETRIDE_python_API.md:456`, `docs/agents/ROCKETRIDE_typescript_API.md:438`, `packages/client-python/src/rocketride/mixins/execution.py:~148`, `packages/client-typescript/docs/guide/methods/use.md:67`, `packages/client-typescript/src/client/client.ts:1432`.
- **The clause conflates omitting the parameter with passing the string `'none'`.** They take different branches:
  - `packages/ai/src/ai/modules/task/task_engine.py:340` — omitted → `None`; `'none'` → the **non-empty string** `'none'`.
  - `:1551` — the gate is `if self._pipelineTraceLevel:`, plain truthiness. `None` is falsy; **`'none'` is truthy.**
  - The comment three lines above (`:1544-1547`) says why it matters: *"synthetic tool-call traces arrive regardless of trace level."* Confirmed: `packages/ai/src/ai/modules/data/data_conn.py:844 _emit_tool_trace` is called from six sites (`:949, :981, :990, :1008, :1010, :1030`), **none gated on trace level**, and routes through `monitorOther('DBG', …)` — the same channel the C++ debugger uses — so the supervisor turns it into an `apaevt_trace` that lands in the `:1551` handler.

| `pipelineTraceLevel` | C++ lane/invoke traces | tool-call traces | `if self._pipelineTraceLevel:` | analytics |
|---|---|---|---|---|
| omitted (`None`) | none | emitted | falsy → skipped | **empty** |
| `'none'` | none | emitted | **truthy → runs** | **populated from tool calls** |
| `'metadata'`/`'summary'`/`'full'` | emitted | emitted | truthy | populated |

- **Trigger:** a pipeline with tool invocations run with an explicit `pipelineTraceLevel='none'`.
- **Expected vs actual:** the new prose says `componentStats`/`slowestDocs` stay empty; they are populated from tool calls.
- **Production impact:** mild — some extra tool-call analytics, nothing broken. But this PR's entire deliverable is that the documentation matches the code, so the standard applies to its own new prose.
- **Introduced** (new prose making a new, falsifiable, incorrect claim; it replaced prose that was wrong in a different way).
- **Corrective direction:** stop asserting equivalence. Say `'none'` is the engine's default level and emits no lane-write or invoke traces, and tell readers to **omit** the parameter when they want nothing recorded at all. Apply identically across all five sites — the PR's own established discipline.
- **Regression-test criterion:** not a code change, so none. The code-side fix (normalise `'none'` → `None` at `task_engine.py:340`, or compare explicitly at `:1551`) deserves its own issue and would make the docs' natural reading true.
- **This is exactly the blocker raised by the current CHANGES_REQUESTED review** (joshuadarron, 2026-09-03, on this head). I verified every step of it independently — the C++ parse table, the truthiness gate, and the six ungated `_emit_tool_trace` call sites — and it holds.
