@tanishq-eradala Reviewed at head `f96da150`. The diagnosis is right — the annotation, docstring, and body genuinely disagreed — but the remedy breaks two in-repo consumers, both reproduced at the head:

1. The MCP monitor treats the result as a dict: `visibility.py:165` does `status.get('state', 0)` → `AttributeError` on the typed object (nine `.get()` sites in that module).
2. The web status endpoint rejects it: `ResultSuccess.data` is `Optional[dict]` (not `Any` as the PR body states), so `response(status)` raises `ValidationError` and `GET /task/status` degrades to an error envelope.

Neither shows up in CI because both consumer suites stub the SDK with plain dicts. Also: the added `TASK_STATE` import is unused (`ruff` F401 → red CI), `extra='ignore'` silently drops any new server-side field (worth at least a debug log), and `ValidationError` becomes a new, undocumented public exception of this method.

Suggested path: keep the typed return, update both consumers in the same PR (or return a model that still supports `.get()`/`__getitem__` during a deprecation window), fix the import, and document the new exception. Then this is a clear improvement.
